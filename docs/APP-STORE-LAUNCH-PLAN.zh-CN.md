# DayVault：个人开发者上架收尾计划

更新：2026-09-14。最初审查基线：`92f4660`，应用版本 1.3.0（build 4）。

开发者已确认：当前 App 停止提供远端 AI 功能，以避免持续模型费用。已有日程、目标和成就保留；本次不改变 Pro 定价，不代表已决定免费首发。范围调整不新建版本标签，也不等于已具备 App Store 提交条件。

其余内容是上架前的验收清单，不代表下列修复已经完成。最初审查依据源码、仓库测试记录与 Apple 官方资料，没有执行新的真机测试或访问开发者账户。停用 AI 后仍需对实际构建回归。

2026-09-14 最终本地验证：Core 57/57、App 单元与集成测试 60/60、UI 19/19 通过，无跳过；Release 配置的 iOS 模拟器构建成功。UI 首轮的多行输入框识别问题修正后，已完整复跑 App 与 UI 共 79 项。模拟器构建不是签名 Archive，以下真机、同步、购买及上架检查仍未完成。

## 1. 这次上架究竟验证什么

建议将 DayVault 定位为：**为已经在坚持某件事的人，记录行动，保留值得回看的里程碑。**

本轮只验证：用户会不会为了回看、保存或分享一段有记录依据的经历，继续使用记录功能。完成一次 App Store 发布是工程目标，用户自发回来才是产品证据；两者不能混为一谈。

当前定位有四个问题：

- “让别人看到我的坚持”和“让 AI 夸我”不是同一种需求。当前去掉后者，先验证有记录依据的成果是否值得用户保存或分享。
- 勾选次数不能证明技能、训练强度或身体变化。不要把“记录了 200 次”写成“超过 90% 的人”；优先呈现日期、次数、休息节奏和用户选择的经历。
- 角色和演出有展示价值，但不能独自承担持续记录的理由。先验证现有演出，不继续用更复杂的动画解释低留存。
- 同时做排程、陪伴、职业规划、健身和成就社区，会使有限的开发时间分散。新健身项目不应变成 DayVault 的下一轮功能扩张。

已有的[竞品与缺口审查](PRODUCT-COMPARISON-2026-09.md)可以继续使用；本轮不再以补齐竞品功能为发布标准。

## 2. 已确认范围与剩余决策

| 决策 | 范围 |
| --- | --- |
| 保留 | 中文今日顺序清单、轻量新增、重复事项、手动创建目标、完成与撤销、公共成就、已有个人成就与本地判定、角色与代表性演出、成果卡预览与保存。 |
| 已确认停用 | AI 排程、聊天与自动文字回应、新个人成就生成、AI 改期建议；不发起模型请求，不要求用户配置代理或密钥。 |
| 优先补齐 | 能找到目标相关记录、成就依据准确、可带走记录的数据导出、非破坏性故障提示、隐私与支持入口。 |
| 暂停新增投入 | 新领域成就、更多装备和动画、排行榜、社交动态、MCP、HealthKit、复杂 AI 记忆与自动改期。 |
| 仍待决策或验收 | Pro 保留，是否免费首发另行决定。iCloud、Calendar、小组件仍需相应签名与真机验收，不能因移除 AI 就自动视为已通过。 |

“基础功能离线可用”不等于“应用没有联网行为”。隐私说明必须依据最后实际提交的构建填写。

首发免费是此前建议，不是已确认或已执行的变更。若已有真实购买用户，必须保留其权益。缩减功能不能删除已有记录、个人成就或装备；未就绪功能也不能只是挪到“更多”后就当作完成验收。

仓库保留模型指令包、服务端代理和过去的联调资料，仅用于历史查阅，不继续作为本次上架依赖。旧目标中的授权状态不能触发请求，完成反馈和演出不得伪装成新的 AI 回复。历史对话与回忆保留在有相应数据的目标详情中，不占首页入口。

## 3. 当前代码距离可提交版本的差距

### P0：发布前解决，或从本次发布范围明确移除

1. **验收停用 AI 的请求边界。** 检查新装、旧目标已授权、完成事项、重大成就和重新启动时均不请求模型，直接调用旧服务入口也应拒绝。验证先前保存的计划、个人成就定义、历史内容仍可使用；不得通过清库停用功能。无需为本次发布补建模型用户鉴权与计费服务。
2. **隐私与支持仍需发布准备。** [SettingsView.swift](../DayVault/Features/Settings/SettingsView.swift) 在最初审查时只有隐私摘要，没有政策或支持链接。[PRIVACY.md](../PRIVACY.md) 已按当前范围调整，但仍须提供可访问的页面和联系方式。最初审查未找到 `PrivacyInfo.xcprivacy`，需按 App 与 Widget 实际使用的 required-reason API 补充并检查归档报告。移除模型请求不会免除其他隐私申报。
3. **Pro 承诺与交互有具体缺陷。** 商品缺失时仍显示 `$14.99`，而 [EntitlementStore.swift](../DayVault/Services/EntitlementStore.swift) 的购买方法直接返回；[InsightsView.swift](../DayVault/Features/Insights/InsightsView.swift) 图表仍固定 30 天。保留销售就必须修复并做真实沙盒验收；本地 StoreKit 配置不等于线上商品已经可用。
4. **签名和同步不能由模拟器证明。** 项目共享配置未填 Team，模拟器默认不启用 CloudKit。开发者账户是否配置完成未知。需要核对实际 App ID、App Group、iCloud 容器、发布签名与生产 schema；保留同步时测试双设备、离线及冲突，不只测试单机启动。
5. **锁屏隐私需要验收。** [DayVaultWidgets.swift](../DayVaultWidgets/DayVaultWidgets.swift) 的锁屏样式直接展示事项标题，未见隐私敏感标记或用户隐藏标题选项。需处理敏感内容显示并在真机锁屏状态验证；本次没有证据表明已发生泄露。

### P1：记录产品的可信度与有限维护责任

- 补充版本化数据导出，验证导出的目标、记录和成就是否完整可读；单项 Calendar 导出不是整库备份。不要先扩建复杂同步平台。
- [PersistenceController.swift](../DayVault/PersistenceController.swift) 本地容器创建最终失败会 `fatalError`。补安全错误页与支持路径，不通过清库“修复”。已有真实 V1→V2 迁移测试应继续保留并回归。
- 核对公共隐藏成就的中间信号与最终线索可达性。仓库[既有问题记录](PRODUCT-COMPARISON-2026-09.md)列出了多数规则进度跳变的问题，本轮未重新运行这些规则测试。
- 目标历史至少可追溯到来源记录；已解锁资格保留，但修正来源后不得继续显示失效的证明或 AI 原文。

## 4. 低预算工具与费用

若已有 Mac 与测试 iPhone，开发工具不必再采购。先用 Xcode、模拟器、现有单元/UI 测试和自己的手机；发布和 TestFlight 使用 Apple Developer Program。个人会员为每年 99 美元或可用地区的当地定价，个人开发者会以个人姓名列示；免费 Apple Account 也可先做个人设备测试。[Apple 会员说明](https://developer.apple.com/support/compare-memberships/)

隐私及支持页可以先用免费 GitHub Pages，不需要营销网站或付费建站工具；页面必须在目标地区实际可访问并有有效联系方式。[GitHub Pages](https://docs.github.com/en/pages/quickstart)

不建议首轮购买广告、付费分析 SDK、云真机套餐或外包测试服务。停用模型请求后，当前 App 不再产生新的模型调用费用；Apple 会员、设备和维护仍可能有成本。这不自动取消开发者以前订购的外部服务，也不会撤回旧服务商已处理的数据。

## 5. 七天小样本验证

先招募 5–8 位已有真实习惯的 iPhone 用户，让他们按原有计划使用，不要求额外训练或每日打卡。这是发现问题的小样本，不是证明市场需求或统计留存率。

| 时点 | 做什么 | 记录什么 |
| --- | --- | --- |
| 第一天 | 不讲解地创建并完成第一条记录，找到对应成就。 | 是否完成、卡点、是否必须求助。 |
| 后续计划日 | 按个人原有节奏使用，不由研究者每天催促。 | 哪些打开是自发的，哪些只是配合测试。 |
| 第七天 | 查看自己的里程碑并选择是否保存。 | 实际保存行为、准确性、为什么值得保留；不强迫公开分享。 |

可以事先定一个内部观察线：若 8 人中不足 6 人独立完成首次记录，先修入口；若几乎无人自发回看或保存，就停止增加动画，重新检查记录需求。小样本达到这些数值也不等于产品市场匹配。

至少做一轮真实设备回归：

- [ ] 新装不配置服务、不授权 Calendar/通知仍可新增与完成。
- [ ] 新装和旧数据升级后均不发起模型请求；旧授权、重复事件和直接服务调用不能绕过停用状态。
- [ ] 已有目标、个人成就、本地进度和历史内容保留，不因功能收紧而清空；新个人成就生成入口不再提供。
- [ ] 飞行模式、强退重启、跨午夜、编辑/删除/撤销后，记录和成就一致。
- [ ] 从真实旧版本升级，ID、重复规则、实际时间、成就与穿搭不丢失。
- [ ] 成就不因重复事件反复解锁；回看演出不增加进度；休息日规则准确。
- [ ] 分享预览和锁屏不意外暴露私人内容。
- [ ] 大字体、VoiceOver、Reduce Motion 与较小屏幕可用。
- [ ] 保留的通知、Calendar、Widget、iCloud、购买分别完成相应真机/沙盒验收。
- [ ] 覆盖最低受支持 iOS 与当前 iOS；不能只根据 iOS 26.2 模拟器测试宣称 iOS 18 全部通过。

记录丢失、错误授奖、隐私问题未解决，不进入公开发布。反馈用简单表格或 GitHub Issues 即可，报告里不要上传用户的完整私人记录。

早期计划的“20 名测试者、七天、99.5% 无崩溃”是项目自定目标，不是 Apple 通用 iOS 上架门槛。外部 TestFlight 的首个构建需要 Beta Review；小样本试用不能替代必要功能测试。[Apple 外部测试说明](https://developer.apple.com/help/app-store-connect/test-a-beta-version/invite-external-testers)

## 6. 个人开发者的实际发布步骤

1. **确认地区和账号。** 确认个人会员、测试设备、首发地区和本次功能范围。不要默认全球上架。中国大陆需要核查适用的 ICP 备案及相关材料；欧盟需核实 DSA 身份与联系信息要求。[Apple 地区信息](https://developer.apple.com/help/app-store-connect/reference/app-information/app-information)
2. **冻结一个可发布构建。** 修复范围内阻断项，配置真实签名与所需能力。目前上传要求 Xcode 26 或更新版本、iOS 26 SDK 或更新版本；编译 SDK 要求与最低部署系统是不同设置。[当前 SDK 要求](https://developer.apple.com/news/upcoming-requirements/)
3. **建立 App Store Connect 记录并归档上传。** 准备应用名称、Bundle ID、版本与构建号；Xcode Archive → Validate/Distribute → 上传。GitHub 标签不是 App Store 发布记录，无需删除原有标签来“重新开始”。[Apple 发布流程](https://developer.apple.com/help/app-store-connect/get-started/app-store-connect-workflow)
4. **准备商店资料。** 真实截图、准确中文介绍、支持网址、隐私网址、年龄问卷、出口合规回答及审核备注。支持页需包含实际联系方式；不要直接把开发 README 当作商店介绍。[版本资料要求](https://developer.apple.com/help/app-store-connect/reference/app-information/platform-version-information)
5. **完成 TestFlight，再提交审核。** 把问题修复到新构建，选择真正验收过的版本。需要后端的功能在审核时必须可用；按实际功能提供审核说明。首发建议选择手动发布，获批后再检查一次资料和支持入口。
6. **限定投入，但保留维护。** 建议先给修复和试用两至三周投入窗口，不保证该时间内审核通过；遇到阻断问题缩减发布范围，不跳过验证。上线后首月每周预留支持时间，此后继续处理安全、兼容性和记录访问问题。

App Store 要求提交完整可用的产品；“实验”可以是开发者的商业目标，不能成为残缺测试版的说明。不要把未就绪功能暗藏在发布版，之后绕过审核启用。涉及第三方 AI 的个人数据须明确披露接收方并事先取得明确许可。[App Review Guidelines：2.1、2.2、2.3.1、5.1.2](https://developer.apple.com/app-store/review/guidelines/)

隐私政策需可访问，App Store Connect 的隐私问卷按实际数据处理填写，并随实践变化更新；没有广告 SDK 不自动等于“没有数据收集”。[Apple 隐私申报](https://developer.apple.com/help/app-store-connect/manage-app-information/manage-app-privacy)

## 7. 给下一款健身 App 留下什么

DayVault 的收获应是一次真实发布、一个可靠记录基础，以及哪些里程碑有人愿意保存的证据，不是再积累一批未经验证的功能。

新项目先选一个人群和一个问题，例如“已有固定训练计划的人，如何用最少操作看到最近十二周的真实进展”。先找五位符合条件的人看他们现在的记录方式和具体困难，不先做完整教练、饮食、社交和排行榜。健康数据、身体指标与训练建议需要另外审查，不能直接照搬日程记录的隐私和同步方案。

如果不准备承担任何上线后维护，TestFlight 实验比发布一个长期依赖远端服务却无人维护的 App 更合适。若以后停止服务，提前通知，保留可行的数据访问/导出路径，不让服务停用变成用户记录消失。

## 待确认的三件事

- 首发地区，以及是否已有个人开发者会员和可用 iPhone。
- Pro 是否继续作为首发销售功能；停用 AI 不代表同时确认免费首发。
- 可投入的收尾时间与上线后的最低维护安排。
