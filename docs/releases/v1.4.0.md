## 中文

v1.4 是 DayVault 这轮实验的收尾版。日常记录、公共成就和角色演出保留；App 不再提供需要开发者持续支付模型费用的 AI 排程与聊天。已有计划、目标、个人成就和历史陪伴记录不清空。

想继续用 AI 处理自己的记录，可以使用新加入的本地 MCP 服务。它面向 Codex、Claude Code、Gemini CLI 等支持 stdio 的工具，读取用户主动导出的单个目标快照，并生成新增事项草案。用户把草案传回 iPhone，预览并确认后才保存。文件往返由用户操作，没有实时连接、账号绑定或后台模型请求。电脑端面向 macOS / Linux，Windows 的文件权限保护尚未验证。

### 本版变化

- 设置增加“MCP 文件交换”，可以选择目标、预览导出范围、保存 JSON，以及检查导入草案。
- MCP 提供目标上下文、事项查询和新增事项草案三种工具，以及 `dayvault_plan` 提示词。模型和账号由外部工具提供，DayVault 不托管模型服务。
- 草案只允许新增有日期、无具体时刻、不重复的事项；每批 1–20 条，日期为目标时区的今天至未来 14 天。现有事项、完成状态和成就不授予外部写入权限。
- 保存前再次检查目标、期限、休息日、日期和重复项。未确认不写入；重复导入不能重复创建同一批事项。
- 中英文 README、接入指南和隐私说明按当前实现重写。版本链接保留独立列表，旧标签和说明不覆盖。

导出的快照不含笔记、聊天、回忆、Calendar 数据或隐藏成就规则。不过，目标名称和事项标题本身也可能包含私人信息。外部 AI 工具可能将它们发送给模型提供商；本地 MCP 不能保证外部模型离线，也不承担所选工具的费用。

版本号为 1.4.0，构建号 5。项目仍是源码发布，不含 App Store 安装包。收尾范围不包括排行榜、社交动态、挑战商城或新的 AI 养成系统；也不表示日后不会处理缺陷。

### 验证记录

本轮完整回归通过：Core 71/71、App 单元与集成测试 76/76、UI 22/22、MCP 33/33。App 和 UI 共 98 项，没有失败或跳过，覆盖草案预览、取消、确认保存及重复导入。MCP 检查包含官方 SDK 客户端连接本地子进程，以及禁止网络调用条件下的完整文件流程。

Release 配置的 iOS 模拟器构建通过，构建产物的版本已核对为 1.4.0、构建号 5。最后一轮 Core 校验修改后，另复跑 16 项 MCP App 集成测试，全部通过；这是已有测试的子集，不额外计入总数。本次没有把模拟器构建当作真机签名归档或 App Store 验收。

发布后修正了一项 CI 配置：GitHub 的 `macos-15` 默认选择较旧的 Xcode，导致 SwiftData 并发类型检查失败。主分支的检查现明确使用 Xcode 26.2，与项目要求一致；没有关闭并发检查或改动数据模型。v1.4.0 标签保留原提交，CI 配置修订可在[主分支工作流](https://github.com/Jack-Li-Npu/DayVault/blob/main/.github/workflows/checks.yml)查看。

停用 App 内 AI 时的独立基线为 Core 57/57、App 单元与集成 60/60、UI 19/19，Release 模拟器构建通过。本轮结果不与该基线相加。

本地协议测试不等于在 Codex、Claude Code、Gemini CLI 的真实账号中完成模型联调。三家的接入写法按官方文档整理，没有因此声称所有模型都能稳定生成合格草案。

已知日期限制：导入按目标时区验证和保存，但今日清单按设备时区选择范围，跨时区后仅日期事项可能出现在相邻日期。这一既有显示问题尚未修复。

真机权限、跨设备 CloudKit、购买沙盒、真实旧版升级和锁屏隐私仍属于上架前检查。Pro 继续保留，没有新增付费墙或改变售价。项目级再分发许可证仍待确认；本说明不代表授予新的许可。

## English

v1.4 is the closing release for this DayVault experiment. It keeps daily recording, the common achievement catalog and character animations. In-app AI scheduling and chat are disabled, so the developer does not need to fund ongoing model calls. Accepted plans, goals, personal achievements and historical companion records remain.

The new local MCP server provides an optional path for people who want to use their own AI tools. Codex, Claude Code, Gemini CLI and other stdio clients can read a user-exported snapshot for one goal and prepare a new-item proposal. The user transfers that file back to the iPhone, reviews it and confirms before saving. There is no live connection, account linking or background model request. The server targets macOS / Linux; file-permission protection on Windows has not been verified.

### Changes

- Settings gains “MCP 文件交换” (MCP file exchange), with goal selection, export-range preview, JSON export and proposal import review.
- The MCP server exposes goal context, record lookup and proposal creation, plus the `dayvault_plan` prompt. The external client provides the model and account; DayVault runs no hosted AI service.
- Proposals contain 1–20 new, date-only, non-recurring items, dated from today through 14 days ahead in the goal's time zone. External tools cannot alter existing items, completion states or achievements.
- Confirmation rechecks the goal, deadline, rest days, dates and duplicates. There is no write before confirmation, and reimporting a batch cannot duplicate its items.
- Chinese and English introductions, setup guides and privacy notes describe the current implementation. Version links remain separate from language navigation, and older tags and release notes stay intact.

Exports exclude notes, conversations, memories, Calendar data and hidden achievement rules. Goal and item titles may still be private. An external AI client may send them to its model provider; running MCP locally does not make the model offline or cover that client's charges.

The app and widget use version 1.4.0, build 5. This is a source release, not an App Store binary. The experiment does not add a leaderboard, social feed, challenge marketplace or new AI companion economy. A closing release is not a promise never to fix bugs.

### Verification

The full regression passed 71/71 Core, 76/76 App unit and integration, 22/22 UI and 33/33 MCP tests. The 98 App and UI tests had no failures or skips and cover proposal preview, cancellation, confirmed saving and repeated import. MCP checks include an official SDK client connected to a local subprocess and the full file workflow with network calls disabled.

The Release-configuration iOS Simulator build passed, and the built product was verified as version 1.4.0, build 5. After the final Core validation change, all 16 MCP App integration tests passed again. That run is a subset of the existing suite, not an additional test count. The simulator build is not a signed device archive or App Store acceptance.

A post-release CI correction pins Xcode 26.2 on the main branch. The older default Xcode on GitHub's `macos-15` runner failed SwiftData concurrency type checks. The correction matches the project's existing toolchain requirement without disabling checks or changing data models. The v1.4.0 tag keeps its original commit; see the [current workflow](https://github.com/Jack-Li-Npu/DayVault/blob/main/.github/workflows/checks.yml) for the CI-only correction.

The separate baseline after in-app AI removal passed 57/57 Core, 60/60 App unit and integration, and 19/19 UI tests, plus a Release simulator build. Current counts are not added to that baseline.

Local protocol tests are not end-to-end model sessions in Codex, Claude Code or Gemini CLI accounts. Their configuration examples follow official documentation, without claiming that every model reliably produces valid proposals.

Known date limitation: imports are validated and saved in the goal's time zone, but Today selects its range using the device time zone. After crossing time zones, a date-only item may appear on the adjacent day. That existing display issue is not fixed.

Physical-device permissions, multi-device CloudKit, purchase sandbox checks, upgrades from actual older builds and lock-screen privacy still need App Store preparation. Pro remains, with no new paywall or pricing change. The project-wide redistribution license is awaiting confirmation; these notes do not grant a new license.
