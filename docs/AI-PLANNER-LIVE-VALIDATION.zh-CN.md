# AI 帮我排：真实链路修复记录

> 本发布文档已脱敏：`api.example.com`、`example-model` 等仅替代私人配置，不代表真实测试服务商或可用模型。测试状态和耗时保留，实际连接设置仅保存在被 Git 忽略的本地文件。

日期：2026-09-10（Asia/Shanghai）。本轮用户明确授权将项目排程指令、输出结构和合成测试输入发送到 `api.example.com`。没有发送私人日记、真实日程或 Calendar 数据，没有保存生成的测试日程，没有发布远端服务。

## 为什么之前仍像旧版本

1. App 没有接口地址时直接使用 Swift 的 `LocalGoalPlanner`，其中固定写着“理清方向、完成核心、练习与调整”。它不读取服务端 Skill。
2. 原启动脚本只临时设置模拟器环境变量。代理停止或启动方式改变后，App 可能重新进入本地模板路径。
3. 结果卡片无论来源都写“AI 草案”，让本地演示看起来像真实模型结果。
4. 即使连上代理，原结构中也有中转不兼容的字段，且长计划容易超过原 60 秒超时。

## 对照证据与本轮处理

- 相同合成输入“我想让自己变好”，原 schema 返回 HTTP 400；只移除发送副本中的 `uniqueItems` 后返回 HTTP 200，并提出一个澄清问题。完整应用 schema 不变，去重在本地校验器中继续执行。
- 完整演讲请求曾出现约 61 秒的 HTTP 504。改用 Responses 流接收，只有收到 `response.completed` 才提取结果，拒绝中断流、部分 JSON 和失败事件。服务端请求上限 135 秒，初次排程客户端 150 秒。
- 不切换模型或降低思考强度。一次 Chat Completions 兼容性探测返回 404，未将这条备用路径接入产品。
- 代理对成功结果附加模型配置与指令版本响应头；App 根据实际调用路径显示“本地演示 · 非 AI 生成”或“AI 生成 · 待你确认”。版本由服务端响应头提供，不信任模型自己编写的来源文字。这里表示请求配置，不是对第三方实际运行模型身份的独立认证。
- 启动时重新打包指令；Deno 监测生成包变化。模拟器保存不含密钥的 `aiPlannerEndpoint`，代理关闭时明确报连接失败，不静默回退演示。普通 UI 自动测试强制走本地，避免意外付费调用。

## 后续修复：本地 IPv4 与故障分层

截图中的 `::1:8000 Connection refused` 是 IPv6 回环连接失败；本地代理只监听 IPv4。App 与启动脚本统一使用 `http://127.0.0.1:8000`，旧的 HTTP localhost / IPv6 回环 8000 端口配置在请求前自动归一，保留路径和查询参数。远端地址、HTTPS 和其他端口不变。

连接失败、客户端等待超时和中转超时不再共用“启动本地代理”的提示。代理保留安全的上游 HTTP 状态；App 只展示固定错误类型和数值状态，不展示原始响应、密钥或请求正文。中转超时明确说明代理已响应，不要求用户反复重启代理。取消请求不显示连接故障，失败不会回退为本地演示。

本次增量通过 46 项服务端测试和 13 项 iOS 单元测试，覆盖旧地址归一、实际请求地址、客户端超时、上游状态、取消及失败后重试成功。首次测试发现 Foundation 对 IPv6 host 的括号表示有差异，已同时兼容两种表示并重新通过全部单元测试。这修复了本地连接选择与错误解释，不意味着消除了第三方中转的延迟或可用性波动。

两项排程 UI 回归也重新通过。修复版已安装到当前 iPhone 17 Pro 模拟器，正常启动，持久化接口为 `http://127.0.0.1:8000`；没有清空数据库。本地健康接口返回 ready、`example-model`、指令 `1.1.0`，其中 `aiVerified: false` 明确表示健康检查不验证模型。

本次真实联调仍未通过：六周演讲目标在 62.461 秒后返回 `provider_timeout`；随后用截图的合成目标“6天完成英语演讲准备”，在 61.646 秒后返回代理 HTTP 502，错误体为 `provider_timeout`、`upstreamStatus: 504`。因此不能声称已恢复稳定生成。约 60 秒的服务商网关超时是推断，HTTP 504 则是实际响应证据；需要服务商排查路由/超时，或由用户另行授权更换线路。没有擅自更换模型、降低思考强度或用固定模板代替失败结果。测试脚本现默认使用六天目标，并打印安全的上游状态码。
