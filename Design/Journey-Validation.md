# 日常记录与搭档：验收记录

## 本轮实现范围

默认进入今日顺序清单。只填标题即可保存，具体时间、待安排、重复等位于高级选项。目标可不创建，AI 可不开启；公共成就和本地记录不依赖网络。

个人成就采用独立命名空间和冻结规则。明确授权后，每个目标生成一个完整批次；并发同步按完整代际确定一批，已获得的历史资格保留。AI 只提案，本地计算进度和解锁，不授予公共装备。

折纸伙伴按开启陪伴后的真实记录日累计成长。补录旧记录不冒充共同经历；双人演出可跳过、回看，回看不增加进度。隐藏态采用受控模糊文案，避免模型在线索中输出精确条件。

七天调整需要预览和确认。执行与撤销重新读取日历、检查授权版本、事项版本、已开始状态、冲突和固定周期频率，再一次保存；不自动删减任务或修改重复规则。

- Core：57 项通过，含真实 V1 磁盘数据库迁移、三类个人规则、历史补录、时区与周期锚点。
- 服务端：30 项通过，含中文契约样例、不可信输出、伪造引用和配置检查。
- App：40 项通过，其中 Journey 集成测试 25 项；包含保存失败整批回滚、再次确认成功及撤销保存失败保护。
- UI：15 项通过；包含精简首页、仅日期记录、可选搭档、演出跳过/回看、成就分组及大字体/减弱动态效果。
- 真实指定模型：2026-09-10 合成探针收到 `HTTP 400 / model_not_supported`；未替换模型，未发送个人记录。契约测试不是远端 AI 已上线的证明。
- 仍需签名真机验证：两台设备离线后 CloudKit 汇合、系统 Calendar 权限撤销/变更、通知及小组件、VoiceOver 实际朗读、设备性能与能耗。模拟器测试不替代这些发布门槛。

## 陪伴是否有额外价值：小范围比较方案（尚未执行）

目的不是评选哪个动画更漂亮，而是确认真实记录回应是否让用户感到努力被看见。

1. 招募同意参与的用户，先正常记录七天；不要求更多运动或更长工作时长。
2. 在一次相同里程碑中比较两种版本。角色、六秒动画、展示时长、字体、音效完全相同。
   - A：只呈现程序计算的次数、日期跨度。
   - B：保留相同统计，增加一条引用用户真实记录的回应；私人留言只有单独授权才使用。
3. 随机分组；小样本可交叉体验并交换顺序，明确这是体验访谈，不把十几个人的结果当作统计显著结论。
4. 记录：是否觉得回应准确、是否感到被看见、是否嫌打扰、是否愿意保存/分享；检查点击来源的比例与错误事实投诉。
5. 不以使用时长或逼迫连续打卡作为成功指标。不因缺席降级，不用羞耻、虚假稀有度或付费提示制造压力。

继续投入陪伴的条件：B 比 A 更有意义，且没有增加事实误读或打扰。若仅动画受到喜欢，先保留轻量记录和成就，不继续扩张聊天功能。
